# Channel plugins

The mobile app's channel for each runtime (`docs/protocol.md`, [ADR 0042](../docs/adr/0042-a-bridge-on-each-host-serves-the-mobile-app.md), proposed): the code that runs inside a sandbox, in the runtime's own process, and listens for enclos's bridge on a Unix socket in the sandbox home.

| Folder | Runtime | What it is |
| --- | --- | --- |
| `hermes/enclos/` | Hermes | A gateway platform plugin. `protocol.py`, `outbox.py` and `lines.py` use the standard library only and are tested with the `enclos-protocol` crate's fixtures and their own tests (`just hermes-plugin`); `adapter.py` is Hermes's side |

enclos's binary carries these files and writes them into the agent's sandbox with `enclos runtime configure <sandbox>/<agent> --channel app`. `prototype/m4/README.md` records what this plugin's first runs in a real Hermes showed, on a Mac: the socket, the plugin's loading and cron delivery. Linux is still to run.

The channel's `PLATFORM_HINT` in `protocol.py` tells the agent what the app renders: markdown, attachments and [static HTML artefacts](../docs/protocol.md#files). For a page, the agent writes one self-contained UTF-8 `.html` file and sends `MEDIA:/absolute/path/page.html` on its own line. The viewer supports inline CSS and data images or fonts; scripts, remote assets, relative files, forms and automatic outgoing navigation are meant to be unavailable, which the app's probes have not all shown yet (design §14). Same-page anchors stay in the viewer; when the person taps a main-frame HTTP(S) link, the app shows its host and address and, once confirmed, opens the website in the preferred browser's Custom Tab on Android where supported. Automatic navigation is meant not to launch it. HTML in message text stays literal. Keep this hint and the app's rendering contract together when changing the capability.
Native questions use Hermes's `send_clarify` adapter hook and its clarify registry (`tools/clarify_gateway.py`: `get_pending`, `resolve_gateway_clarify`, `mark_awaiting_text`, the `SKIPPED`/`CANCELLED` sentinels, and an entry's `session_key`, `choices`, `multi_select`, `event` and `response`). The plugin saves a card's exact native entry and session key, resolves an explicit `question.answer` into that waiter, and sends durable `question.update` settlement; an answer never becomes another chat turn. A question's native event and the retirement hook close expired, skipped, answered and cancelled cards; an entry the plugin can no longer read cancels its card, and closing the channel cancels the native wait with it. Reconnect sync reaffirms live entries and expires cards missing after a Hermes restart. A question the bridge refuses, and one for an older bridge, or outside the card's bounds, goes as Hermes's own numbered text, split into bounded chunks rather than cut. The plugin leaves a card's entry as Hermes made it: in the composer, an option's number or text or "skip" answers, and other prose cancels the question and reaches the agent as a message. A registry missing any of these is logged once, and questions go as text. CI's `hermes-latest` job runs the real-Hermes tests (`ENCLOS_HERMES_SOURCE`) against Hermes's default branch, so such a change fails there. `runtime configure` sets `agent.clarify_timeout` to an hour for the app's agents.

The bundled model-invoked [`app-questions` skill](hermes/enclos/skills/app-questions/SKILL.md) is explicitly registered when Hermes supports plugin skills; the always-loaded hint retains essential `clarify` guidance. Runtime packaging includes the Python module and skill in each configured agent's own plugin folder.

Runtime approvals reuse the durable question delivery path with separate `runtime_approvals` negotiation and typed approval answers. `runtime_approvals.py` binds only the native prompt's exact request ID, preserves its offered actions and full-command/Deny-only gate, and observes settlement without replacing Hermes's own handler. The app's own accepted action has a correlated receipt; a decision from another native surface closes as Resolved without an invented action. Older runtimes, older bridges and oversized definitions use complete, independently fenced typed-command chunks. Trusted approval sends bypass image/notice inference and reject oversized encoded frames before persistence. Session/always remain Hermes pattern grants; the card names the request's native pattern keys and offers neither when the snapshot has none. Card and text show the command with hidden characters written out and flag non-ASCII. A request the adapter cannot bind or observe is sent as text rather than reported as a delivered card; a request gone from Hermes without an observation closes as expired after a short grace. They do not alter Enclos sandbox policy.

Held tasks ([ADR 0066](../docs/adr/0066-held-tasks-stay-with-the-runtime.md), proposed) are read from Hermes's kanban board through `hermes_cli.kanban_db`: `list_boards`, `pin_first_board_resolution`, `kanban_db_path`, `DEFAULT_BOARD`, `list_tasks`, `get_task`, `unblock_task`, the `Task` fields `id`, `title`, `assignee`, `status`, `created_by`, `created_at` and `last_failure_error`, and the `task_events` columns `id`, `task_id`, `kind`, `payload` and `created_at` (read from its `SCHEMA_SQL`); a resume also uses `hermes_cli.kanban_db_connect.connect`, Hermes's writer, which reads never open (they use `tasks.read_only`). When one is missing, `held_tasks.py` names it in the gateway's log and the plugin does not announce `held_tasks`. It reads the boards again after Hermes's board hooks and `on_kanban_dispatch_tick`, and every 30 seconds. `test_held_tasks.py` runs a stand-in board everywhere and a real board, in a temporary `HERMES_KANBAN_HOME`, with `ENCLOS_HERMES_SOURCE`.

Which tasks are held. `blocked` tasks are always listed. `triage` is listed only when `hermes_cli.kanban_db.VALID_STATUSES`, which is optional, names it; a Hermes without that list is read as having no triage (not assumed to have it), so its blocked tasks are still read and reported as they change. A `blocked` task's hold is its latest event of `_BOUNDS`: `blocked` or `gave_up` (`_HOLDS`, which give its reason), `unblocked` or `created`. A `triage` task is held only while its latest event of `_TRIAGE_BOUNDS` is `block_loop_detected`, the event of Hermes's loop breaker (`BLOCK_RECURRENCE_LIMIT`, which explains that behavior; the plugin does not import it): the others are `created`, `imported`, `status`, `specified`, `unblocked`, `promoted`, `promoted_manual`, `completed` and `archived`, each a way into or out of triage. Membership is decided by that latest *boundary* event; the task's `revision` is its latest event of *any* kind, a comment included.

Why such a triage task is not resumed from the app. It is reported `resumable: false`, with "Decide on the agent's task board." in place of what resuming does, and the bridge refuses its resume before asking the plugin. The plugin still checks a resume that reaches it (from an older bridge) as for a blocked task, then answers `unsupported` before Hermes's writer opens, whether or not this Hermes has `specify_triage_task`: that call takes no revision and changes any task in `triage`, and Hermes offers no call that resumes a task only while it is still held as the app saw it. `specify_triage_task` is named here to explain Hermes's own way out of triage, done on the board; the plugin neither calls nor needs it. Blocked tasks resume as before, through `connect` and `unblock_task`, with their inherited race: a task unblocked and blocked again between the plugin's check and the unblock is resumed at its newer hold.

The optional native approval tests use only source imports, temporary profile homes and simulated waiting work: set `ENCLOS_HERMES_APPROVAL_SOURCE` to a modern checkout, `ENCLOS_HERMES_LEGACY_SOURCE` to an older checkout, and `ENCLOS_HERMES_TEST_DEPS` to a test-only dependency directory, then run `python3.13 -I -m unittest discover -s channels/hermes/tests -p test_runtime_approvals.py`. No gateway, model, command or user runtime is started. CI's `hermes-latest` job runs them with the default branch as the modern checkout and, as the older one, the last Hermes before the exact approval API (`c10474fb`), and fails if any skips.
