# Channel plugins

The mobile app's channel for each runtime (`docs/protocol.md`, [ADR 0042](../docs/adr/0042-a-bridge-on-each-host-serves-the-mobile-app.md), proposed): the code that runs inside a sandbox, in the runtime's own process, and listens for enclos's bridge on a Unix socket in the sandbox home.

| Folder | Runtime | What it is |
| --- | --- | --- |
| `hermes/enclos/` | Hermes | A gateway platform plugin. `protocol.py`, `outbox.py` and `lines.py` use the standard library only and are tested with the `enclos-protocol` crate's fixtures and their own tests (`just hermes-plugin`); `adapter.py` is Hermes's side |

enclos's binary carries these files and writes them into the agent's sandbox with `enclos runtime configure <sandbox>/<agent> --channel app`. `prototype/m4/README.md` records what this plugin's first runs in a real Hermes showed, on a Mac: the socket, the plugin's loading and cron delivery. Linux is still to run.

The channel's `PLATFORM_HINT` in `protocol.py` tells the agent what the app renders: markdown, attachments and [static HTML artefacts](../docs/protocol.md#files). For a page, the agent writes one self-contained UTF-8 `.html` file and sends `MEDIA:/absolute/path/page.html` on its own line. The viewer supports inline CSS and data images or fonts; scripts, remote assets, relative files, forms and automatic outgoing navigation are meant to be unavailable, which the app's probes have not all shown yet (design §14). Same-page anchors stay in the viewer; when the person taps a main-frame HTTP(S) link, the app shows its host and address and, once confirmed, opens the website in the preferred browser's Custom Tab on Android where supported. Automatic navigation is meant not to launch it. HTML in message text stays literal. Keep this hint and the app's rendering contract together when changing the capability.
Native questions use Hermes's `send_clarify` adapter hook and its clarify registry (`tools/clarify_gateway.py`: `get_pending`, `resolve_gateway_clarify`, `mark_awaiting_text`, the `SKIPPED`/`CANCELLED` sentinels, and an entry's `session_key`, `choices`, `multi_select`, `event` and `response`). The plugin saves a card's exact native entry and session key, resolves an explicit `question.answer` into that waiter, and sends durable `question.update` settlement; an answer never becomes another chat turn. A question's native event and the retirement hook close expired, skipped, answered and cancelled cards; an entry the plugin can no longer read cancels its card, and closing the channel cancels the native wait with it. Reconnect sync reaffirms live entries and expires cards missing after a Hermes restart. A question the bridge refuses, and one for an older bridge, or outside the card's bounds, goes as Hermes's own numbered text, split into bounded chunks rather than cut. The plugin leaves a card's entry as Hermes made it: in the composer, an option's number or text or "skip" answers, and other prose cancels the question and reaches the agent as a message. A registry missing any of these is logged once, and questions go as text. CI's `hermes-latest` job runs the real-Hermes tests (`ENCLOS_HERMES_SOURCE`) against Hermes's default branch, so such a change fails there. `runtime configure` sets `agent.clarify_timeout` to an hour for the app's agents.

The bundled model-invoked [`app-questions` skill](hermes/enclos/skills/app-questions/SKILL.md) is explicitly registered when Hermes supports plugin skills; the always-loaded hint retains essential `clarify` guidance. Runtime packaging includes the Python module and skill in each configured agent's own plugin folder.
