# ADR 0006: evidence for the Seatbelt baseline

The evidence [ADR 0006](../../docs/adr/0006-seatbelt-deny-by-default.md) asked for, gathered on macOS 26.5.2 (Apple Silicon) on 2026-10-22, and how. The ADR records the decision; this folder is how to run it again.

## Method

- Each workload ran through enclos itself, in sandboxes of a throwaway enclos home outside `~/.claude` and every other deny-list folder (a home under a denied folder makes `git` fail under either baseline). `ENCLOS_SEATBELT_BASELINE=allow-default` compiled the earlier baseline for the comparison; without it, enclos compiles `(deny default)` with [`deny-default.sb`](../../src/backend/seatbelt/deny-default.sb).
- [`trace.py`](trace.py) ran each command while a bounded `log stream` collected the denials tagged with the sandbox's name, then counted them by operation and argument. The results below came from its first version, which did not yet fail on a truncated capture, a stream error, a missing canary or lines it could not read, cut arguments at ` (`, counted allows and denials together, and neither cleared an inherited `ENCLOS_SEATBELT_BASELINE` nor checked which baseline a command ran on: the lists below are what it read, not proof that nothing else was refused. Its current version reads `log stream --style ndjson`, in which a tagged denial's message is the denial and then the tag on a line of its own (macOS 26.5.2); it was checked there on a one-write workload under `(deny default)`, its two canaries and the write read and nothing else counted, and the workloads below were not run again with it. Before enclos compiled the new baseline, the first allowances came from a compiled policy edited by hand and run with `sandbox-exec`, and from `(allow <operation> (with report))` traces under `(allow default)`, read with a capped `log show`.
- An allowance went into the list only when a workload or one of enclos's tests needed it or looked it up: pseudo-terminals and `ioctl` came from the tests (a session's own terminal), the rest from the workloads. Not every one is a failure without it: a failure is recorded for libinfo, `configd`, the notification memory, `trustd`, pseudo-terminals and `ioctl`; the others (membership, `logd`, `bsd.dirhelper`, `sysctl` reads and process information) are kept because the workloads looked them up. Two lookups the workloads made are no longer allowed, since none failed without them: the notification center, through which a sandbox posts a notification a host process waits for (`notifyutil -p` seen by a host `notifyutil -1`, macOS 26.5.2), and `diagnosticd`, which serves the unified log to its readers (`log` itself refuses to run in a sandbox, so what it would serve another program was not shown). Signals need none: the host-service rules allow the sandbox's own.

## Workloads and results

| Workload | `(allow default)` | `(deny default)` |
|---|---|---|
| A shell, `ls`, Python with `ssl`, `git --version`, `curl` through the proxy | runs | runs, once the libinfo, `configd` and notification memory are allowed |
| `git clone` over HTTPS through the proxy | runs | runs |
| `enclos runtime install hermes` (its installer, `uv`, Python, Node, npm, ripgrep, ffmpeg, `agent-browser`, Chrome for Testing's download) | all 20 steps, 90 s | all 20 steps, 85 s, once `com.apple.trustd.agent` is allowed (its downloads failed with OSStatus -26276 without it) |
| `hermes --version`, `profile list`, `config get model`, `doctor` | the same output | the same output |
| `enclos agent add <sandbox>/main` (`hermes profile create`) | made | made |
| The gateway, started by launchd | runs, no error in its log (an earlier build, below) | runs, no error in its log |
| `agent-browser open https://example.com` | Chrome cannot create its socket folder | Chrome exits before it starts; which denial stops it first is not recorded |
| `enclos policy test` | READY: 72 closed, 10 inconclusive | READY: 72 closed, 10 inconclusive |
| Every test of enclos (real Seatbelt sessions, services, probes, limits) | passed before | passes, once pseudo-terminals and `ioctl` are allowed |
| `ps` | cannot run: it is setuid, which Seatbelt refuses under any policy | the same |

The gateway's `(allow default)` run used a build that passed `ENCLOS_SEATBELT_BASELINE` to the services it installs. enclos no longer does, and `enclos launch` refuses to start a service while it asks for another baseline, so that run cannot be repeated: a service runs only on `(deny default)`.

The 10 inconclusive probes read folders macOS's privacy protection hides outside the sandbox too (Mail, Messages, Safari, Contacts and the like), and the crontab, of which there was none. The probes that act on the host if a rule fails run only in CI, on its macOS 15 and macOS 26 runners, under both baselines: `every_escape_probe_fails_in_a_new_sandbox` under `(deny default)` and `every_escape_probe_fails_under_allow_by_default_too` under `(allow default)`. The allowances were gathered on macOS 26.5.2; macOS 15 runs the same tests on the same list. A run before the probes knew the baseline's refusal ([run 39894401237](https://github.com/victorbonnet/enclos/actions/runs/39894401237), `4ed4eed`) read them inconclusive under `(deny default)`, printing `Code=-10661` and `Can't get application "Finder". (-1728)`, not the rules' -54 and -600: the tools fail before the `lsopen` and `appleevent-send` rules are reached. No probe was open. Both tests then passed on both runners at commit `8c3386b` ([run 39895358898](https://github.com/victorbonnet/enclos/actions/runs/39895358898), 2026-10-23 UTC), the probes taking either refusal on either baseline. From `b02a348` they count the baseline's refusal only on `(deny default)`, still taking the rules' there too, and from `1cf4bf2` only the baseline's there; the rules' own refusals count only on `(allow default)`. `the_host_services_close_on_the_baseline_and_on_the_rules` and `every_escape_probe_fails_under_allow_by_default_too` passed on both runners at `b02a348` ([run 39902548610](https://github.com/victorbonnet/enclos/actions/runs/39902548610); the run is red because `every_escape_probe_fails_in_a_new_sandbox` failed on its check of the report's wording, with no probe open, fixed in `90d32d0`), and with the counting of `1cf4bf2` at `7b36101` ([run 39979423146](https://github.com/victorbonnet/enclos/actions/runs/39979423146)).

Refused under `(deny default)`, and done without: `com.apple.SystemConfiguration.DNSConfiguration` and `com.apple.coreservices.launchservicesd` (Node), `com.apple.analyticsd` and `system-fsctl (_IO "A" 20)` (`codesign`, run by the installer), `mach-priv-task-port` on itself (Python). Refused under both: the deny list's paths (reads of their metadata by `hermes doctor` and the gateway), `com.apple.SecurityServer` (the keychain rules), and connections to `mDNSResponder` (names resolve through the proxy).

## Not shown

- What Chrome for Testing needs under `(deny default)`: it starts under neither baseline yet; under `(allow default)` the write rules stop it, and under `(deny default)` which denial stops it first is not recorded (design §14).
- A model call, and the gateway answering on Telegram: both need a login these runs had not.
