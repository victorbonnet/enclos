# enclos 0.3.1

This release fixes `sandbox create` on Linux, where it used Seatbelt unless told otherwise.

```bash
curl -fsSL https://enclos.dev/install.sh | bash
```

## Fixed: `sandbox create` uses the host's default backend

On Linux, `enclos init` said `Default backend: bubblewrap.` and wrote it to `config.toml`, but `sandbox create` without `--backend` still used `seatbelt`, so the command the guides give failed with `uses the seatbelt backend, which this host cannot run`. It now takes the default backend `config.toml` names: Seatbelt on a Mac, bubblewrap on Linux. Where `config.toml` names none, because no backend could run when `init` wrote it, `sandbox create` takes the first backend that runs now. `--backend` still names another, and a `default_backend` enclos cannot read is refused, naming the file.

The same commands now run as written on macOS and Linux. The README, the [getting started guide](https://github.com/victorbonnet/enclos/blob/main/docs/getting-started.md), [policy compilation](https://github.com/victorbonnet/enclos/blob/main/docs/policy-compilation.md) and [enclos.dev](https://enclos.dev/) now cover Linux: policy compilation gains bubblewrap's limits (`memory` from `64M`, `cpu` from 0.01 to 1024 cores, `cpu_seconds` and `file_size` refused) and says that `listen = false` is declared, not held, on bubblewrap.

## Upgrading

Run the install command above. Your sandboxes, agents, policies and audit log carry over: the state database has not changed since 0.3.0, so no `enclos init` is needed. A sandbox keeps the backend it was made with.

## Known gaps

The [known gaps of 0.3.0](https://github.com/victorbonnet/enclos/blob/main/docs/release-notes/0.3.0.md#known-gaps) all still apply.

## Checking this release

```bash
gh attestation verify enclos-aarch64-apple-darwin.tar.gz --repo victorbonnet/enclos
gh attestation verify enclos-x86_64-unknown-linux-musl.tar.gz --repo victorbonnet/enclos
gh attestation verify enclos-aarch64-unknown-linux-musl.tar.gz --repo victorbonnet/enclos
```

The installer checks the archive's SHA-256 and the binary's version. The attestation says which workflow run, commit and repository built the archive.
