# enclos 0.1.0

The first release. enclos runs [Hermes](https://hermes-agent.nousresearch.com) agents in Seatbelt sandboxes on an Apple silicon Mac, with a policy for what each sandbox may do and an audit log of every command that changes something.

```bash
curl -fsSL https://enclos.dev/install.sh | bash
```

The [getting started guide](https://github.com/victorbonnet/enclos/blob/main/docs/getting-started.md) takes you from there to talking to an agent.

## What it does

- **Sandboxes:** each has its own home, proxy and policy, from a template: `minimal`, `mcp-only` or `assistant`. Every connection goes through its proxy, and `enclos net log` shows them.
- **Policies:** immutable versions with `history`, `diff` and `rollback`. A change that needs a restart waits as the pending policy until you apply it. `enclos policy test` runs escape probes that must fail.
- **Secrets:** kept in your Keychain, granted to a sandbox or to one agent, so each agent can have a Telegram bot of its own.
- **Services:** the proxy and the Hermes gateway run under launchd, with no enclos daemon, and come back at each login.
- **Checks:** `enclos doctor`, `state check` and `state repair`, `audit verify`, and JSON output for every command.

## Tested on

- **macOS 27.2:** the full [manual test](https://github.com/victorbonnet/enclos/blob/main/docs/manual-e2e.md) and the test suite, by hand, on 2026-11-01. `policy test`: 71 of 85 probes shown closed, none open. The other 14 cannot be shown from a terminal: 13 folders macOS keeps the terminal out of too, and a crontab that did not exist.
- **macOS 15 and 26:** the test suite, in CI on every change. Milestone 1's end-to-end run was on macOS 26.5.2.

CI has no macOS 27 runner yet, so a later change could break it unnoticed until the next hand run. `policy test --host-services` has not run on macOS 27.

## Known gaps

- **Threat model:** enclos protects against accidental damage by agents you mostly trust. It is not a defense against malicious code exploiting the kernel.
- **Apple silicon Macs only.** Linux is the next milestone. Hermes is the only runtime.
- **Environment variables:** any process of yours can read another's start-up environment, sandboxed or not, Apple's own programs aside. A Hermes gateway gets its secrets through a file instead, but a `connect` or `exec` session still gets them as variables. Don't keep secrets in exported shell variables while sandboxes run.
- **Your processes are visible:** a sandbox can list what runs on your Mac.
- **Agents share a sandbox's files:** isolation is per sandbox. A secret granted to one agent is kept apart from the others, not hidden from them.
- **Browser tools:** Chromium does not start in a sandbox, so Hermes's browser tools are unavailable.
- **Limits:** `open_files` is the only limit Seatbelt can hold. CPU time, memory, file size and CPU share are refused when the policy is stored, never stored and ignored.
- **Programs:** a policy cannot say which programs may run; an `[exec]` section is refused.
- **A process that detaches carefully:** one that closes its inherited descriptors and leaves its group and parent is not found by `sandbox stop`. It keeps its Seatbelt restrictions, and `state check` names it when its program is in the sandbox's folder.
- **Network log:** a connection is logged as long as enclos can write its state.
- **Not notarized:** the binary is not signed with an Apple Developer ID. The installer's download runs without a prompt; a browser download would be blocked.
- **Upgrades:** state may not carry over between 0.x releases. A release that changes it says so, and you start again from `enclos init`.

Smaller findings are in [#137](https://github.com/victorbonnet/enclos/issues/137).

## Checking this release

```bash
gh attestation verify enclos-aarch64-apple-darwin.tar.gz --repo victorbonnet/enclos
```

The installer checks the archive's SHA-256 and the binary's version. The attestation says which workflow run, commit and repository built the archive.
