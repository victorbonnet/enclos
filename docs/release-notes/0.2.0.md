# enclos 0.2.0

This release removes the `mcp-only` template, which is a breaking change for any sandbox made from it.

```bash
curl -fsSL https://enclos.dev/install.sh | bash
```

## Breaking change: `mcp-only` is gone

The `mcp-only` template had the same rules as `minimal`, so it promised a difference that did not exist. `enclos sandbox create --template` now takes `minimal` or `assistant`.

**If you have a sandbox made from `mcp-only`,** it keeps running under its active policy, and `status`, `policy show` and new sessions work as before. `policy allow`, `runtime install` and `policy refresh` stop with this error:

```text
unknown template `mcp-only`: this enclos has minimal, assistant
```

To fix it, run `enclos policy edit <sandbox>` and change `extends` to `minimal`. The rules stay the same, and those commands work again.

**To reach a remote MCP server,** start from `minimal`, allow its host with `enclos policy allow`, then tell the runtime of it with its own commands through `enclos connect`.

## Upgrading

Run the install command above. Your sandboxes, agents, policies and audit log carry over: the state database has not changed since 0.1.0. Apart from the fix above, nothing else is needed.

## Website

[enclos.dev](https://enclos.dev/) is simpler, with short guides to [getting started](https://enclos.dev/getting-started.html) and [how a policy compiles](https://enclos.dev/policy-compilation.html). The second one and [the docs](https://github.com/victorbonnet/enclos/blob/main/docs/policy-compilation.md#every-setting) now list what each template can do and every policy setting.

## Tested on

- **macOS 15 and 26:** the test suite, in CI on this commit.
- **The upgrade:** a sandbox made from `mcp-only` by a build from before this change, then used and moved to `minimal` with this one, by hand on macOS 27.2.

The [manual test](https://github.com/victorbonnet/enclos/blob/main/docs/manual-e2e.md) was not repeated for this release. It last ran for 0.1.0, and removing the template is the only change to the binary since. CI has no macOS 27 runner yet.

## Known gaps

The [known gaps of 0.1.0](https://github.com/victorbonnet/enclos/blob/main/docs/release-notes/0.1.0.md#known-gaps) all still apply.

## Checking this release

```bash
gh attestation verify enclos-aarch64-apple-darwin.tar.gz --repo victorbonnet/enclos
```

The installer checks the archive's SHA-256 and the binary's version. The attestation says which workflow run, commit and repository built the archive.
