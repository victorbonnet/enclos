# enclos 0.4.0

This release adds a third template, `autonomous`, for an agent that looks after your Mac, and fixes `sandbox create` on Linux, where it used Seatbelt unless told otherwise.

```bash
curl -fsSL https://enclos.dev/install.sh | bash
```

## The `autonomous` template

`autonomous` is for an agent that looks after the host: sorting and moving your media, tidying folders, installing and updating tools with Homebrew. Under `assistant`, each of those folders has to be granted as a workspace first, and anything off ports 80 and 443 has to be listed. This template is proposed in [ADR 0058](https://github.com/victorbonnet/enclos/blob/main/docs/adr/0058-an-autonomous-template-writes-everywhere-but-keys.md) (#188) and built in #239.

**What it gives:**

- **Writes everywhere you can write** (`write = ["/"]`), your own files and media included, but `/dev`, which keeps the baseline's rules, so your other terminals stay closed.
- **The public web on every port** (`public_ports = "any"`), still through the sandbox's proxy, which logs every connection.

**What stays closed:**

- the sensitive deny list, for reads and writes: SSH, cloud and Git credentials, keychains, browser data, password managers, `~/Library/LaunchAgents`;
- enclos's own files and other sandboxes;
- enclos's own program, which the services run outside every sandbox, by every path that leads to it;
- **read-only paths**, a new list the sandbox reads but cannot change, remove, rename or create. By default it holds your shell's startup and logout files (`~/.zshrc`, `~/.zshenv`, `~/.zprofile`, `~/.zlogin`, `~/.zlogout`, `~/.bashrc`, `~/.bash_profile`, `~/.bash_login`, `~/.bash_logout`, `~/.profile`, `~/.config/fish`), since your next terminal would run what is written there;
- loopback, link-local and metadata addresses, and private addresses unless a host is allowed and listed in `private`;
- the host services: opening apps or URLs, Apple Events, launchd jobs, the Keychain, signals outside the sandbox. `sandbox stop` still ends everything the sandbox runs.

**Higher risk.** Nothing stops it changing or removing your own files, so keep backups. Commands are not filtered: what `rm -rf` can remove is what the policy lets the sandbox write. Anything your Mac later runs from a file it wrote, such as a program on your `PATH`, a file a startup file sources, a Git hook or an app, runs outside the sandbox. `enclos sandbox create --template autonomous` says so on standard error before it creates the sandbox.

**Narrow it** in the sandbox's `policy.toml`: `write = [...]` lists the folders it may write instead, `read_only` replaces the read-only list and `read_only_add` adds to it, and `public_ports = "web"` or `mode = "allowlist"` narrow the network. Both settings are new, and any policy may set them. `policy show` and `policy diff` show the read-only paths and the ports public mode opens. `policy test` probes the read-only paths and enclos's program under a grant, and says what the policy opens that it therefore does not probe.

**macOS only, for now.** Only the Seatbelt backend builds it. On bubblewrap, keeping a path unchanged inside a folder the sandbox writes needs read-only binds under a writable root, and a bind of `/` would replace the sandbox's own `/tmp`, `/run`, `/dev` and `/proc` with the host's; Landlock cannot carve paths out of a tree it allows. Until that is built, bubblewrap refuses a write grant of `/`, a read-only path inside a folder the sandbox writes, and a grant holding enclos's program, when the policy is stored and at each compile, so `autonomous` cannot be used on Linux.

**What is shown:** a backend test under real `sandbox-exec` on macOS 27.2. The sandbox wrote the user's files and moved a folder of them; changing, removing, renaming or creating a read-only path, reading or writing the deny list, writing enclos's files or changing its program, moving the home, enclos's folder or the program's folder, and making a hard link to any of them were refused. A whole `policy test` run under the template, and a real Homebrew install and media sorting from the sandbox, are not shown yet (design §14). ADR 0058 is still proposed.

## Fixed: `sandbox create` uses the host's default backend

On Linux, `enclos init` said `Default backend: bubblewrap.` and wrote it to `config.toml`, but `sandbox create` without `--backend` still used `seatbelt`, so the command the guides give failed with `uses the seatbelt backend, which this host cannot run`. It now takes the default backend `config.toml` names: Seatbelt on a Mac, bubblewrap on Linux. Where `config.toml` names none, because no backend could run when `init` wrote it, `sandbox create` takes the first backend that runs now. `--backend` still names another, and a `default_backend` enclos cannot read is refused, naming the file (#247).

## Docs

The same commands now run as written on macOS and Linux. The README's quick start lists the Linux requirements. The [getting started guide](https://github.com/victorbonnet/enclos/blob/main/docs/getting-started.md) no longer says the default stays `seatbelt`. [Policy compilation](https://github.com/victorbonnet/enclos/blob/main/docs/policy-compilation.md) covers both backends: it gains bubblewrap's limits (`memory` from `64M`, `cpu` from 0.01 to 1024 cores, `cpu_seconds` and `file_size` refused), says that `listen = false` is declared, not held, on bubblewrap, and lists the `autonomous` template, `read_only` and `public_ports`, with what bubblewrap refuses of them.

## Upgrading

Run the install command above. Your sandboxes, agents, policies and audit log carry over: the state database has not changed since 0.3.0, so no `enclos init` is needed. A sandbox keeps the backend it was made with.

Policy snapshots are unchanged too. `read_only` and `public_ports` are left out of a snapshot at their defaults (none, and the web ports), so a policy that sets neither keeps its snapshot and its hash. A Seatbelt policy names read-only paths and enclos's program only where a grant covers them, so a sandbox made from `minimal` or `assistant` compiles as it did in 0.3.0.

If you script `policy test --json`, it gains `open_by_policy`, a list that is empty unless the policy writes outside the home or opens every port.

## Tested on

- **macOS 15 and 26:** the test suite, in CI on this commit. The `autonomous` template's backend test also ran under real `sandbox-exec` on macOS 27.2.
- **Ubuntu 24.04 (x86_64 and arm64) and 26.04:** the test suite and the bubblewrap, confinement, cgroup, systemd and libsecret tests, in CI on this commit. CI's bubblewrap tests now create their sandbox with no `--backend`, so each depends on the default. The release workflow also runs each Linux archive in a Debian 13 container, and the x86_64 one on Ubuntu 26.04.

The [manual test](https://github.com/victorbonnet/enclos/blob/main/docs/manual-e2e.md) was not repeated for this release, on a Mac or on Linux.

## Checking this release

```bash
gh attestation verify enclos-aarch64-apple-darwin.tar.gz --repo victorbonnet/enclos
gh attestation verify enclos-x86_64-unknown-linux-musl.tar.gz --repo victorbonnet/enclos
gh attestation verify enclos-aarch64-unknown-linux-musl.tar.gz --repo victorbonnet/enclos
```

The installer checks the archive's SHA-256 and the binary's version. The attestation says which workflow run, commit and repository built the archive.
