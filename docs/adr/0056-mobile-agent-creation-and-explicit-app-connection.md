# Mobile agent creation and explicit app connection

Amends [0055](0055-the-host-user-can-provision-sandboxes-from-a-paired-phone.md): the host's user can create a new agent in an existing sandbox and explicitly connect an existing agent to the app. Creation uses the runtime's profile command and refuses an existing profile; connecting can adopt a profile the runtime already has, but never creates a missing one, preserving [0023](0023-agents-made-inside-a-sandbox.md)'s explicit adoption boundary. The owner's inventory includes profiles without an app channel so partial setup remains visible and recoverable. Optional bounded initial instructions replace only the new profile's inherited identity file (`SOUL.md` for Hermes), copied inside the sandbox to the adapter's fixed path. Omitted instructions, model and tool preferences retain the runtime's defaults; accurate model and tool choices need a host/runtime catalog before the phone offers them.

Connecting grants only that agent one private app token, configures its channel, and restarts the whole sandbox through the existing engine lifecycle. This requires a separate confirmation because changing per-agent secret grants changes the sandbox's launch policy and ends its running sessions; creation alone must not imply that interruption. Exact active or pending app grants reuse their token, while a first connection chooses an unused random reference rather than granting an unrelated ungranted secret. Failure before the grant can leave an ungranted token for host cleanup; retry chooses a fresh reference. Unrelated pending policy changes or unapplied file edits require host review. An exact pending change adding only this agent's app grant can resume, and explicit reconnect remains available after partial failure. Provider login remains on the host.
