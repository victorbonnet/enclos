# OpenClaw agent transfer observations

Source inspection on 2026-11-17 used the installed OpenClaw **2026.11.3**, commit `847611dcaa3bf0e2783335f961dd1fd0580e4d9f`, and matching `@openclaw/codex` package. `dist/build-info.json` and `package.json` establish that revision and shared/agent schemas **22/27**. This report separates source inspection, fixture round trips, and the remaining migration acceptance.

## Supported preservation boundary

Retain each native agent ID. Enclos display names can differ. Native database admission compares the recorded agent owner with the requested ID and refuses a mismatch. No public agent rename or complete session-key move API was found in the installed CLI/SDK. Changing SQLite ownership metadata would bypass that contract. The native agent CLI supports independent identity/display fields. Sources: [agent CLI](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/docs/cli/agents.md), [owner validation](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/src/state/openclaw-agent-db-schema-read.ts).

Use the public native commands, with the selected sandbox's `OPENCLAW_STATE_DIR` and `OPENCLAW_CONFIG_PATH` pinned:

```sh
openclaw backup sqlite create --agent main --repository <private-repository> --json
openclaw backup sqlite verify <snapshot-directory> --json
openclaw backup sqlite restore <snapshot-directory> --target <fresh-agent-database-path> --json
```

Each snapshot has exactly `manifest.json` and `database.sqlite`. The CLI resolves the configured `<agentDir>/openclaw-agent.sqlite`; it does not require the agent directory to be under the default state tree. Creation uses the SQLite online backup API, validates source and generated copy, compacts the copy, includes committed WAL content, and embeds referenced cold transcripts. Verification checks digest, size, integrity, foreign keys, version, role, and agent ownership. Restore preserves the verified bytes and refuses an existing target or SQLite sidecars. Activation is a separate offline step. This preserves the native database's memory, session/transcript, local auth, and plugin records together; it does not capture arbitrary adjacent files. Sources: [SQLite snapshots](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/docs/cli/backup.md#sqlite-snapshots), [CLI source selection and restore](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/src/commands/backup-sqlite.ts).

Native `claws export` is not this migration format. Claws are experimental setup packages, require offline ownership for installed-state operations, and exclude credentials, bindings, and local memory paths. Sources: [Claws](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/docs/cli/claws.md).

## Auth without replacing destination shared accounts

Shared credentials live in the shared state database; local credentials and routing/cooldown state live in each agent database. An agent-only snapshot therefore does not include its inherited shared base. Personal accounts have separate identity-scoped ownership and are not enumerated by ordinary shared-account readers. Environment and SecretRef values are separate external inputs. Sources: [OAuth storage](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/docs/concepts/oauth.md#storage-where-tokens-live), [credential semantics](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/docs/auth-credential-semantics.md).

The public SDK provides:

- `loadAuthProfileStoreWithoutExternalProfilesAsync` from `openclaw/plugin-sdk/agent-runtime`: persisted-only, read-only preparation; external CLI profiles are excluded. Calling with no `agentDir` selects shared credentials. Passing `agentDir` normally merges shared and local stores; `{inheritedAuthDir: agentDir, allowKeychainPrompt: false}` selects the local-only view. The native profile-removal flow uses that local-only pattern.
- `resolvePersistedAuthProfileOwnerAgentDirAsync` identifies profile ownership where provenance is needed.
- `updateAuthProfileStoreWithLock` from `openclaw/plugin-sdk/provider-auth`: accepts explicit `stateDir`, `agentDir`, `sharedStoreWrite`, save options, and a synchronous updater. It returns `null` on failure; the compatibility wrapper also converts thrown errors into `null`.

For a per-agent transfer, materialize inherited source profiles into **the restored destination agent's local store**, adding only IDs absent from that restored local store. Keep its own profiles and ordering authoritative. Select explicit destination `agentDir`, `stateDir`, and `sharedStoreWrite: false`, with `saveOptions: {filterExternalAuthProfiles: false, syncExternalCli: false}`. Do not replace the destination global database.

**The conventional `main` path is a trap:** `upsertAuthProfileWithLock` and `upsertAuthProfileAsync` internally enable `sharedStoreWrite: true`; native `isSharedAuthProfileWrite` then treats an explicit conventional main agent directory as a shared write. Use the update API with `sharedStoreWrite: false` for main-local restoration. Run auth preparation in a dedicated helper process with selected state/config environment; an inherited runtime auth scope can override an explicit reader directory. Sources: [public agent-runtime exports](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/src/plugin-sdk/agent-runtime.ts), [provider-auth exports](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/src/plugin-sdk/provider-auth.ts), [store readers/writer](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/src/agents/auth-profiles/store.ts), [shared-write selection](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/src/agents/auth-profiles/shared-store-bootstrap.ts), [compatibility result handling](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/src/plugin-sdk/provider-auth-write-compat.ts).

OAuth credentials may be rotation-sensitive. Source export and destination activation must form an exclusive handover; copying a refresh credential into two running owners is not a safe synchronization mechanism. Native writes retain their OAuth fencing/account checks and can refuse a stale generation. Do not work around those refusals. Source: [OAuth ownership and portability](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/docs/auth-credential-semantics.md).

## Session routing and Enclos identities

The public `session-store-runtime` SDK exposes reads, public-field patches/upserts, deletion, transcript APIs, and store path resolution. Its upsert projects the public entry and does not implement an atomic transfer of session windows, participants, private fields, and plugin-owned bindings to a different key. Native `sessions import` creates a bounded untrusted reference copy and explicitly does not resume or bind the native source session. Neither operation is a lossless session-key rename. Sources: [session helper contract](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/docs/plugins/sdk-runtime/agent.md), [session public-field writer](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/src/plugin-sdk/session-store-runtime.ts), [session import limitations](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/docs/cli/sessions.md).

Enclos owns its transport route registry. In [channel.js](../../channels/openclaw/channel.js), native session keys use the saved route's peer; ordinary peers are `sha256(JSON.stringify([conversation,person]))`. Home peers are `sha256(JSON.stringify(['enclos-home',accountId,agentId,conversation]))`. [transport.js](../../channels/openclaw/transport.js) validates those derivations when loading routes and binds each route to a person.

Consequently a versioned **Enclos-owned** imported-route record can reindex destination conversation IDs while retaining the original peer and source provenance. It must validate the peer against recorded source inputs, bind the destination person explicitly, preserve account/native agent IDs, and never transfer receipts or outbox. This is an Enclos-owned extension, implemented in the transfer helper and channel route loader; ordinary and Home remapping tests cover it. It is not a native session rename API. Historical native participant/creator records remain historical facts; mapping a destination transport person does not authorize rewriting native ownership.

## Codex state, paths, and plugins

For ordinary agent-scoped Codex, its home is `<agentDir>/codex-home`; it contains native configuration, plugins/cache/data, and thread state. OpenClaw auth remains in SQLite, and default agent scope does not consume a copied `codex-home/auth.json` directly. Preserve both the native agent snapshot and the complete stopped per-agent Codex data needed for thread continuation. `homeScope: user`, supervised sessions, remote app servers, or paired-node sessions have additional external owners and cannot be claimed as fully captured by this per-agent package. Sources: [Codex auth and isolation](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/docs/plugins/codex-harness-reference/auth.md), [home resolution](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/extensions/codex/src/app-server/auth-start-options.ts).

Codex session bindings live in the **global** native `plugin_state_entries` namespace `app-server-thread-bindings`, owned by `codex`; an agent-only SQLite snapshot does not carry them. The public `plugin-state-store-runtime` SDK exposes `createPluginStateKeyedStoreV2`, whose bounded entries, lookup and register-if-absent operations can transfer the selected agent’s opaque values without writing SQLite directly. Session keys have the `session-key:<agent>:` or legacy `session:<agent>:` prefix. Registered conversation bindings need a supported native ownership import and currently refuse export. Unrouted legacy records have a narrower reference-only preservation path below.

For a `conversation:<bindingId>` Codex record, ownership evidence is a matching native **current-conversation binding**, not its working directory. The global `current_conversation_bindings.record_json` stores the canonical `SessionBindingRecord`; `metadata_json` and the channel/account/target columns are projections. A Codex-owned record has `metadata.pluginBindingOwner: "plugin"`, `metadata.pluginId: "codex"`, its actual installed `metadata.pluginRoot`, and `metadata.data` with `kind: "codex-app-server-session"`, version 2, the exact `bindingId`, and optional `agentId`, `agentDir`, `workspaceDir`, and `source`. Match `metadata.data.bindingId` to the plugin-state key. Require explicit selected-agent identity and matching configured agent directory; when `source` exists, validate its agent/session/key/store against the selected snapshot too. Codex runtime gives `source.agentId` precedence over `data.agentId`, so contradictory references must refuse. Missing, duplicate, malformed, or unowned registry evidence cannot be repaired by inferring ownership from `cwd`. Sources: [plugin binding record and creation](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/src/plugins/conversation-binding.ts), [registry kernel](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/src/infra/outbound/current-conversation-bindings.kernel.ts), [Codex conversation data](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/extensions/codex/src/conversation-binding-data.ts), [Codex runtime source selection](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/extensions/codex/src/conversation-binding-preparation.ts).

The public `getSessionBindingService()` from `openclaw/plugin-sdk/conversation-binding-runtime` provides `inspectByConversationAsync({channel, accountId, conversationId, parentConversationId?})`, returning `{status: "available", binding: SessionBindingRecord | null}` or `{status: "unavailable"}`. `listBySessionAsync(targetSessionKey)` lists one target; plugin conversation targets usually have the unscoped `plugin-binding:codex:<hash>` form, so listing native agent session keys alone will not enumerate them. Read-only inspection of a completed shared snapshot can supply candidate conversation references for native inspection. Sources: [public inspection and service](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/src/infra/outbound/session-binding-service.ts), [plugin target-key derivation](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/src/plugins/conversation-binding-session-key.ts).

The public writer is `await service.bind({targetSessionKey, targetKind: "session", conversation, placement: "current", metadata, ttlMs?, assertCurrent?})`. It retains the imported `metadata.data.bindingId`, allowing the exact preserved Codex plugin-state record to remain the thread binding. It rechecks the actual channel adapter and native database owner; an unavailable adapter is a refusal. Generic `webchat` bindings are explicitly supported without a registered channel runtime. Other channels need their real native adapter or declared generic support; registering a substitute adapter merely to pass that gate is not an adoption API. The public writer creates fresh destination binding/activity timestamps and has no public expected-absent parameter; the stronger predicate uses a private symbol. Thus a supported semantic reattachment requires a fresh, exclusively owned destination, absence inspection, native bind, and readback, while exact preservation of source timestamps/status through an offline import remains unsupported. Preserve the original record in the export, refuse concurrent or conflicting destination ownership, and do not claim byte-identical registry restoration. Sources: [awaited native binding contract](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/docs/plugins/sdk-runtime/channel.md#awaited-conversation-binding-mutations), [native generic binding and adapter checks](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/src/infra/outbound/session-binding-service.ts).

An unreferenced `conversation:` record may instead be a terminal retirement fence. A conservative classifier requires the public Codex binding reader to accept the value, raw keys limited to `version`, `state`, `retired`, and optional `sessionId`, with `version: 1`, `state: "cleared"`, `retired: true`, no lease, no binding, no native subagent/task payload, and no canonical conversation registry reference. Native binding reads return a thread only for `state: "active"`; ordinary acquisition of the matching retired generation is rejected. Such a minimal record contains no native thread locator or history payload and establishes no selected-agent ownership. It can be reported separately as an unowned terminal fence outside the selected-agent transfer; optionally retain its opaque original in export audit material without activating it or assigning an agent. This is not permission to delete or rewrite the source fence. Native lease release can retain non-`session:` retired keys indefinitely, so accumulation is expected and expiry is not a justification for omission. Every other orphan needs additional evidence or must refuse rather than silently lose continuity or cleanup obligations; an active record never qualifies for terminal-fence exclusion. Sources: [canonical binding codec](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/extensions/codex/src/app-server/session-binding-record-codec.ts), [binding reads and key identity](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/extensions/codex/src/app-server/session-binding-record.ts), [retirement and lease-release policy](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/extensions/codex/src/app-server/session-binding.ts).

An **active orphan** can be retained as opaque, unrouted native data when its physical thread provenance is independently established. This is a transfer-policy inference from the native storage and read contracts, not a new native ownership grant: inspect every configured agent's canonical agent-scoped Codex home successfully; require the record's `binding.threadId` to appear in exactly one home's native thread catalog; require that home to belong to the selected configured agent; require the associated rollout bytes inside the captured home and matching paths; and require no canonical conversation registry reference. Shared/user homes, supervision connections, ambiguous or missing thread IDs, escaping symlinks, absent rollout bytes, leases, pending subagent/task work, and relocation remain refusals. A read-only check of the pinned native Codex thread index is format-specific provenance evidence; the stronger public native check is app-server `thread/read` with `{threadId, includeTurns: false}` on a client bound to that exact Codex home. Native OpenClaw uses this passive read before adoption and verifies that the returned thread ID matches; it does not start a turn. Sources: [passive catalog reads](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/extensions/codex/src/session-catalog-events.ts), [native pre-adoption thread check](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/extensions/codex/src/app-server/thread-policy.ts).

For that narrowly proven case, transfer the original opaque `conversation:<id>` value through the public keyed-store `registerIfAbsent` API together with its owning Codex home, while keeping the native conversation registry absent exactly as on the source. Do not create a registry entry, rewrite the record as retired, assign an invented agent field, or claim that preserving the data reattaches a conversation. A later explicit native bind remains a separate native operation. Record the provenance and orphan classification in the transfer manifest and verify unchanged values after import. This preserves historical native data without manufacturing route authority or silently dropping active binding records.

The native Codex binding codec stores `threadId`, `cwd`, optional `rolloutPath`, configuration fingerprints, optional lease, and native subagent state. Conversation bindings additionally contain `workspaceDir`, optional `agentDir`, and source `storePath`. The installed `native-session-binding-api.js` exports a reader only. No public relocation writer was found. Retaining identical internal sandbox paths can preserve opaque bindings for this specific migration. General relocation remains unverified and must refuse unsupported layouts instead of rewriting protected data. Sources: [binding codec](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/extensions/codex/src/app-server/session-binding-record-codec.ts), [conversation binding data](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/extensions/codex/src/conversation-binding-data.ts).

Native backup intentionally omits plugin `node_modules` and generated `plugin-skills` symlinks. Reinstall/update plugin packages on the target architecture with the native installer (`openclaw plugins update <id>` or `openclaw plugins install <spec> --force`), and rebuild the skills index with `openclaw skills list` or normal session initialization. The matching Codex package declares platform-specific Codex binaries, so copying Pi-installed dependency trees to Ubuntu is insufficient. Preserve plugin declarations/configuration and authored workspace/skills separately. Sources: [archive activation warning](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/docs/cli/backup.md#restore-a-full-archive), [Codex package metadata](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/extensions/codex/package.json).

## Pending work is not sanitized away

Native agent snapshots clear only `state_leases` and `agent_database_leases`. The global sanitizer additionally removes delivery queue rows, but that does not sanitize an agent's pending inputs or restart-recovery fields. Gateway shutdown records recovery before cancelling queued work, and startup can resume interrupted queued/preparing turns. A stopped Gateway therefore does not by itself prove an inert export. Sources: [local snapshot transform](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/src/snapshot/openclaw-snapshot-copy.ts), [sanitizer](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/src/state/openclaw-state-snapshot-sanitizer.ts), [restart recovery](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/docs/concepts/session.md#gateway-restart-recovery).

Use an idle/drained source and refuse unresolved executable pending/recovery state. `/stop` is a supported per-session cancellation operation; no public bulk offline retire-all-recovery API was found. Do not clear protected tables or manufacture terminal/native owner records. A source-specific read-only inspection of the completed snapshot can establish refusal preconditions without mutating its bytes. Cancelled pending inputs do not run automatically; ordinary pending-input counts alone are not a runnable-job count. Sources: [session lifecycle](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/docs/concepts/session.md), [pending-input semantics](https://github.com/openclaw/openclaw/blob/847611dcaa3bf0e2783335f961dd1fd0580e4d9f/docs/concepts/session-tool.md).

Before claiming end-to-end support, verify a stopped, private fixture round trip through native snapshot/restore and native admission, both IDs, inherited-versus-local auth priority (especially main), preserved memory/transcript counts, ordinary/Home remapped routes, Codex thread continuation at identical paths, target plugin reconstruction, and refusal of active/pending or unsupported relocation cases. Never use implementation-only fixtures as evidence of a native migration.

## Native probe evidence

`src/runtime/openclaw/native-roundtrip.py` passed for the default and a second agent on the historical Ubuntu OpenClaw 2026.11.3 private install. It exercises real native snapshot creation, verification, restoration, roster admission, shared versus local credential priority, agent-local restore without shared-store replacement, global Codex binding transfer and workspace preservation. The probe uses public fixture credentials only. Before restoring main’s database, a public shared-auth update with an unchanged updater lets the native lifecycle initialize a fresh shared store; otherwise its legacy-main fallback treats main-local data as inherited shared auth. No machine ownership record is fabricated.

The offline probe against OpenClaw 2026.11.5 used the `main` and `helper` fixture agents. Both restored the native database, agent logins, workspace and Codex binding using the installed SDK. After import, the fixture setting still held its file SecretRef and its provider read from the destination's protected file.

The initial sandbox root bind exposed host-owned ancestors as an unmapped uid and native snapshot staging refused them. Reconstructing the root and home ancestors as session-owned directories, sealed read-only with the original host entries bound read-only, allowed the native guards to pass. Both IDs also passed the same round trip through the built Enclos Bubblewrap backend on Ubuntu. The real Pi-to-Ubuntu continuation still requires acceptance checks.

The real Pi copy has zero current-conversation registry rows, 261 active legacy `conversation:` values, and four agent-session values. Unique thread catalog membership assigns 258 legacy records to the default agent and three to a second agent; their copied rollout files exist under the corresponding captured Codex homes. The legacy catalog and binding paths still name the pre-Enclos host location. The adapter therefore preserves these values **only as inactive per-agent reference files**, alongside the captured rollout bytes, and never publishes them into the destination native plugin store or creates routes. This is distinct from the same-path, unrouted native-record transfer described above: its relocation precondition is not satisfied for these old values. Current Enclos session bindings use the supported unchanged native keyed-store transfer.

The source also exposed a stopped-runtime credential case: its Brave SecretRef points to the engine’s protected JSON delivery file, which `sandbox stop` removes. A public native resolver correctly returned `SECRET_PROVIDER_UNAVAILABLE` / `FsSafeError:not-found`. The generic exporter now stages private copies of the selected agent’s declared credential files, supplies an explicit source-path mapping to the adapter, and removes only those staged copies afterward. Service delivery paths remain untouched, including during a concurrent start. A regression test first failed with exporter exit91 (file absent), then passed success and failure cleanup while preserving a separately created service delivery. No native guard is relaxed.
