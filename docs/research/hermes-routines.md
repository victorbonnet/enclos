# Hermes routines: implementation evidence

Inspected 2026-11-09, against local Hermes commit [`e5ea5fd9cc`](https://github.com/NousResearch/hermes-agent/tree/e5ea5fd9cc) (a v0.22.5 canary). No production routine was created, changed or executed during research.

Rechecked 2026-11-11 against [v0.23.1](https://github.com/NousResearch/hermes-agent/tree/v0.23.1), the latest release then (`git ls-remote --tags`), by reading its source: `cron/jobs.py` still has `create_job` (with `deliver`, `origin`, `script`, `enabled_toolsets`, `workdir`, `no_agent`), `get_job`, `list_jobs`, `update_job`, `pause_job`, `resume_job`, `remove_job`, `use_cron_store`, `_jobs_lock` and its `fcntl` lock, and still validates a working directory's existence; `cron/scheduler_provider.py` still has `CronScheduler.claim_fire` and `fire_claimed`, and `run_one_job` sets up the profile's own secret scope; `gateway/run_adapters.py` creates a secondary profile's adapters inside that profile's runtime scope, so the adapter's routine manager captures its own agent's home. The plugin's tests against a real store ran on the `e5ea5fd9cc` checkout, not on v0.23.1. When a release renames one of these, the plugin turns the `routines` capability off and logs which one.

## Mobile behaviour

The person's four screenshots show an agent-menu **Routines** entry, an agent-scoped list with an empty state and add action, and a create sheet with optional name, schedule, instructions and delivery target. Schedule choices are Daily, Weekly, Monthly, Repeat, Once and Custom; Daily initially shows 09:00. Advanced settings are skills, model, toolsets, script-only execution, a script under the agent's scripts directory and an absolute working directory.

The official [mobile page](https://hermes-agent.nousresearch.com/mobile) is a beta waitlist. The official native mobile source is absent from this checkout; hidden mobile list controls and transport behaviour have not been verified. Community apps with similar names are not evidence for the official app. Official [desktop routine controls](https://github.com/NousResearch/hermes-agent/blob/e5ea5fd9cc/apps/desktop/src/plugins/hermes-bots/cron.tsx) and [dashboard controls](https://github.com/NousResearch/hermes-agent/blob/e5ea5fd9cc/web/src/pages/CronPage.tsx) independently support pause/resume, delete, edit, immediate run and inspection of run state.

## Runtime behaviour

- [`cron/jobs.py`](https://github.com/NousResearch/hermes-agent/blob/e5ea5fd9cc/cron/jobs.py) owns per-agent definitions, file locking and CRUD. Its scoped store is selected by `use_cron_store`; the bridge must not patch `jobs.json`.
- [`cron/scheduler.py`](https://github.com/NousResearch/hermes-agent/blob/e5ea5fd9cc/cron/scheduler.py)'s `create_job_with_scheduler_registration` persists then registers a job. Registration may fail after persistence; that failure must report the saved job and must not invite retrying creation. Later mutations notify the native scheduler provider.
- Native schedules are cron expressions, positive minute intervals and one-shot timestamps. Daily/weekly/monthly choices compile to cron. This revision has a profile scheduling timezone, not per-job timezone: the editor must show the runtime's reported zone rather than silently use the phone's. Intervals represent elapsed time; cron represents wall-clock time.
- Native fields matching the screenshots are `name`, `prompt`, `skills`, `model`/`provider`, `enabled_toolsets`, `script`, `no_agent`, `workdir`, and `deliver`. Null toolsets means defaults; an empty list means no tools. Updates must preserve native fields the editor does not understand.
- The native create function does not enforce script containment itself. The plugin must check that a relative script resolves to a regular file under the active agent's `scripts` directory, including symlinks. Native script-only execution requires a script. An absolute working directory must exist; it grants no new policy access.
- Delivery `local` saves output without sending it; `enclos:<conversation-id>` sends to a specific app conversation, and `enclos` uses the configured Home conversation. App targets need bridge authorization before reaching the plugin. Existing external targets stay runtime-native.
- Native routines have no editable-definition revision or caller-supplied creation id. The adapter needs revision checking and bounded duplicate-request handling; a disconnected or timed-out control cannot safely be retried automatically. Deletion removes the definition and native saved output, but does not promise to cancel already-running work.
- The adapter reuses Hermes's reentrant jobs lock around revision comparison and mutation. Hermes normally takes a cross-process file lock too, but this source revision silently falls back to its in-process lock after a file-lock timeout or failure. App controls are serialized in the plugin; stale-edit protection against a separate native process inherits that limitation. The adapter does not replace Hermes's locking internals or claim unconditional cross-process compare-and-swap under that fallback.

Public background: [Scheduled Tasks](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron) and [Bot-mode routines](https://hermes-agent.nousresearch.com/docs/user-guide/bot-mode#routines). Behaviour above comes from the pinned source and supplied screenshots, not assumptions about the private mobile implementation.

## Verification

On 2026-11-09, protocol and bridge tests passed, including real Unix-socket request routing, authorization, correlation, pagination limits and stale/late replies. The plugin's 50 tests passed, including 18 against real Hermes job stores in temporary agent homes. Scheduler providers and dispatch were controlled test doubles: no production agent, model, script or scheduled execution ran. Android's 54 JVM tests, debug build and lint passed; lint retained the nine existing warnings.

Broader Rust validation passed 1,281 library tests, 67 binary tests, 100 CLI integration tests, 24 documentation tests and the protocol fixtures. Two unrelated library tests could not pass because an existing `nc` listener already occupied 127.0.0.1:41001; its start time and working directory preceded this task, and it was left untouched. Workspace Clippy, formatting and dependency-policy checks passed. No dependency versions changed.

End-to-end delivery, background execution with a stopped phone, DST behaviour in a running sandbox, and Android interaction on a device remain to verify. The design and app spec keep these as pending checks; source inspection and isolated tests do not establish them.
