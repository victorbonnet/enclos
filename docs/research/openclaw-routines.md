# OpenClaw routine observations

Checked against the installed OpenClaw **2026.11.2**, commit `b556fdf457b026574bf0f1e7b4914b15f3f179ce`, on 2026-11-09. The package and its public SDK are a pinned compatibility pair. This records source-confirmed behavior; a successful fixture using an injected facade does not prove a native Gateway probe.

The [public Gateway service documentation](https://github.com/openclaw/openclaw/blob/b556fdf457b026574bf0f1e7b4914b15f3f179ce/docs/plugins/sdk-runtime/gateway-and-nodes.md) exposes `api.registerService` and the service start context's optional `getCron()`. The getter returns a facade tied to that service lease and native scheduler instance. Native `src/plugins/service-cron.ts` checks the lease and current scheduler before and after `list` and `isEnabled`. It caches the same facade while the scheduler remains current. The enclos channel registers a service, advertises routines only while a native list facade exists, and checks both service generation and native facade identity after each awaited read. It never manufactures authenticated Gateway request scope.

The facade's public type is `PluginHookGatewayCronService` in the installed `dist/config-contracts-0_35lKDI.d.ts`. `list({includeDisabled:true})` returns jobs with explicit `agentId`, definition and observed state. The implementation delegates to native `cron.list` without writing the native store. enclos accepts at most 2048 returned jobs, filters exact `agentId`, paginates at most 25 summaries and bounds each response to 44 KiB. Its opaque definition hash excludes execution state and native observation timestamps. A changed definition invalidates the pagination cursor; execution progress alone does not.

Native cron, whole-minute interval and one-time schedules map to the existing protocol without rounding. The protocol supplies one runtime time zone; a native cron time zone different from the Gateway process's effective zone is explicitly unsupported. Event/stream/exit schedules and sub-minute intervals are also unsupported. Native unknown fields and external delivery destinations remain untouched; every summary is read-only. A complete instruction must be present in native `agentTurn.message` or `systemEvent.text` before details can be returned. No missing payload, oversized prompt, name or model is converted into a truncated complete definition.

Mutation parity is **not implemented**. Although the public facade has `add`, `update`, `remove` and optional `enqueueRun`, its published create input lacks complete agent-targeted `agentTurn` and channel delivery fields. Its update has no `expectedConfigRevision` or equivalent definition precondition. The native implementation calls unconditional `cron.update`, `cron.remove` and `cron.enqueueRun` with a lifecycle commit guard; that guard does not compare a routine definition. Reading a hash and then calling these methods would leave a concurrency race. The internal scheduler's stronger precondition methods are not part of this public plugin service contract.

The [public Gateway method dispatch contract](https://github.com/openclaw/openclaw/blob/b556fdf457b026574bf0f1e7b4914b15f3f179ce/docs/plugins/sdk-runtime/gateway-and-nodes.md) requires an authenticated plugin HTTP/RPC request scope. A channel Unix socket callback has no such actor scope. `cron-store-runtime` file helpers likewise do not confer permission to edit native scheduler data. enclos uses neither path as a substitute. Completing mutations requires an upstream public, lifecycle-scoped seam with agent-targeted creation/delivery, atomic expected-definition preconditions for changes/removal/manual runs, and durable create/request outcome semantics. It must not add a second scheduler or retry ambiguous writes.
