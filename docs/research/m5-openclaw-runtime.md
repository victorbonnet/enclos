## Installation and per-sandbox state

- The published package declares Node `>=24.16.0 <25 || >=26.1.0`. Source builds also have a pinned pnpm toolchain; npm installation avoids building the repository/UI in each sandbox. Never substitute an older remembered Node requirement. [Package](https://github.com/openclaw/openclaw/blob/v2026.11.2/package.json).
- Prefer the official **local-prefix** `https://openclaw.ai/install-cli.sh`, with explicit sandbox-local `--prefix`, `--npm`, `--runtime-only`, and `--no-onboard`. The documented runtime-only mode skips Gateway discovery/service refresh/onboarding and, for npm, system Git provisioning. The ordinary installer may provision Homebrew/system packages and is unsuitable as an unexamined substitute. The local installer downloads its private Node, verifies its checksum, and supports machine output. Its current documented Node is 24.22.1; the served script must be inspected and its actual downloads audited at probe time. [Installer internals](https://github.com/openclaw/openclaw/blob/v2026.11.2/docs/install/installer.md).
- Set explicit sandbox-local `OPENCLAW_HOME`, `OPENCLAW_STATE_DIR`, `OPENCLAW_CONFIG_PATH`, workspace and cache paths for every installer, CLI, service and recovery operation. `OPENCLAW_HOME` changes OpenClaw path defaults but some OS-account/package-manager operations still consult the real home. Named runtime profiles are separate installations/state roots, not enclos agents. `.env` in the working directory is untrusted and cannot supply protected runtime controls/provider credentials. [Environment contract](https://github.com/openclaw/openclaw/blob/v2026.11.2/docs/help/environment.md).
- **Before any host-state experiment**, add protection for host `~/.openclaw` and supported named-profile roots; the current sensitive list names `~/.hermes`, not OpenClaw. Refresh existing sandboxes explicitly because policy snapshots are immutable. Verify the sandbox can still use its own relocated state. [Current defaults](../../src/policy/templates/defaults.toml), [ADR 0018](../adr/0018-immutable-policy-snapshots.md).
- Required install domains, optional/native dependency downloads, actual disk use, proxy compatibility, executable/cache/temp writes and browser behavior remain **to probe**. Do not copy the Hermes endpoint list or claim confinement from an installer exit code.

## Agent semantics and observations

- One Gateway serves multiple agents. Each agent has its own workspace, `agentDir`, auth and SQLite session state, normally `<stateDir>/agents/<id>/agent/openclaw-agent.sqlite`. Shared plugin storage may remain shared. Workspace selection alone is not an OS permission boundary. [Multi-agent model](https://github.com/openclaw/openclaw/blob/v2026.11.2/docs/concepts/multi-agent.md).
- An unconfigured installation defaults to `main`, but **`main` is an ordinary removable agent id**, not an immortal built-in. `agents list --json --bindings`, `agents add <id> --workspace <absolute-path> --non-interactive --json`, and `agents delete <id> --force --json` are native operations. Only the last configured agent cannot be deleted. Basic creation can use a running Gateway; role/agent-dir/binding setup requires it stopped. Nonzero results can follow partial work; reconcile the native roster before retry. [Agent CLI](https://github.com/openclaw/openclaw/blob/v2026.11.2/docs/cli/agents.md).
- **Inference for enclos:** separate native default selection from immutable built-in identity; do not hardcode `main` as `BuiltinAgent`. A bounded adapter reader must interpret shared JSON5 config and configured agent paths, including absent/degraded/unknown states. Directory presence or a SQLite file does not establish usable authentication. Status must not read auth contents simply to display login state. [Existing adapter contracts](../../src/runtime/mod.rs), [ADR 0023](../adr/0023-agents-made-inside-a-sandbox.md).
- There is no documented `agents import/export` equivalent. Experimental `claws export` produces a portable package directory; `claws build` makes a `.tgz`; `claws add` has a preview plus exact plan-integrity consent. Claws exclude credentials, sessions and unowned local state, and installed-state commands require offline ownership. This is **limited portable setup**, not Hermes profile/history equivalence. Keep `agent add --from` unsupported initially; assess a native Claw workflow separately under ADR 0026, never extract on the host or invent an enclos archive. [Claws](https://github.com/openclaw/openclaw/blob/v2026.11.2/docs/cli/claws.md), [ADR 0026](../adr/0026-agents-imported-through-the-runtimes-own-export.md).

## Gateway, CLI and dashboard

- Run a foreground `openclaw gateway run` as the sandbox's one runtime service, with `gateway.mode=local`, loopback binding and authentication. **Port 0 is rejected**: CLI/config validation requires 1–65535, unlike Hermes's ephemeral bind. A configured port is only a candidate; process identity and exclusive ownership must prove what enclos opens. Do not broaden loopback egress. [Run implementation](https://github.com/openclaw/openclaw/blob/v2026.11.2/src/cli/gateway-cli/run.ts), [run reference](https://github.com/openclaw/openclaw/blob/v2026.11.2/docs/cli/gateway/running.md), [ADR 0028](../adr/0028-a-runtime-listens-and-its-sessions-reach-its-service.md).
- `OPENCLAW_SUPERVISOR_MODE=external` refuses native service installation/control and self-update. Fresh-process restarts use an explicit handoff; `gateway restart-handoff capabilities/consume --expected-pid ... --json` negotiates it. `OPENCLAW_SERVICE_REPAIR_POLICY=external` is a separate Doctor setting. Plain exit-success versus requested restart must not be guessed. Do not automatically claim durable database ownership: that command has persistent consequences and no automatic unclaim. [External supervision](https://github.com/openclaw/openclaw/blob/v2026.11.2/docs/cli/gateway/restart-and-supervision.md).
- Embedding guidance disables Bonjour and shell snapshots and uses `OPENCLAW_NO_RESPAWN=1` to avoid detached update replacement. It does **not** mean every restart exits: routine restarts can stay in process. Authenticated `hello-ok` establishes RPC readiness; a TCP listener or early challenge does not. Keep channels enabled for this integration. Verify PID/marker inheritance through workers/restarts and whether the listener belongs to the service root or another proven member. [Embedding](https://github.com/openclaw/openclaw/blob/v2026.11.2/docs/gateway/embedding.md).
- Interactive `enclos connect` remains a sandbox shell; show the native `openclaw tui --session agent:<id>:main` or explicit target. TUI Gateway mode and embedded `--local` are distinct; `chat`/`terminal` imply local mode. `openclaw agent --agent <id> --message ...` uses the Gateway; `--local`/`agent exec` are embedded paths. Probe both without accidentally starting a competing writer. [TUI](https://github.com/openclaw/openclaw/blob/v2026.11.2/docs/cli/tui.md), [agent CLI](https://github.com/openclaw/openclaw/blob/v2026.11.2/docs/cli/agent.md).
- `openclaw dashboard --json` neither opens a browser nor starts a service. It returns `browserUrl`, HTTP/WS URLs and port; browser integrations should open the short-lived one-use `browserUrl`, which creates a signed administrator device credential. Shared-auth `url` is different. Preserve auth, avoid logging these values, and probe headless loopback handoff and later Linux forwarding/origin behavior. [Dashboard CLI](https://github.com/openclaw/openclaw/blob/v2026.11.2/docs/cli/dashboard.md).
- OpenClaw already hot-applies most agent/model/channel/plugin changes; some require restart. Avoid blindly applying Hermes's file watcher/USR1 behavior. OpenClaw uses USR2 for manual restart; USR1 starts Node's inspector. Choose and probe a single lifecycle owner and honor saved-but-unapplied configuration. [Hot reload](https://github.com/openclaw/openclaw/blob/v2026.11.2/docs/gateway/configuration/hot-reload.md).

## Secrets and channel accounts

- SecretRefs support `env`, **`file`**, `exec` and `store`. A file provider reads a private, single-link regular file: JSON pointers into JSON or `singleValue`; symlinks/hardlinks are refused and reads bounded. An enclos-owned JSON secret file can therefore avoid service-startup environment values without teaching OpenClaw dotenv syntax. This is a **proposed adapter strategy**, not yet shown under Seatbelt. Enclos keeps permissions, atomic writes, protection and cleanup; config holds references only. [SecretRef contract](https://github.com/openclaw/openclaw/blob/v2026.11.2/docs/gateway/secrets/secretref-contract.md), [ADR 0034](../adr/0034-a-service-reads-its-secrets-from-a-file-its-sandbox-alone-reads.md).
- Supported reference fields include provider API keys, eligible per-agent auth-profile key/token refs, Telegram account `botToken`, Discord account tokens and Gateway auth. OAuth/rotating login material is excluded from read-only reference resolution and remains runtime-owned state. Do not claim all providers use the same login/file marker. [Credential surface](https://github.com/openclaw/openclaw/blob/v2026.11.2/docs/reference/secretref-credential-surface.md).
- Multiple Telegram/Discord bot accounts bind to agents by account id. The conventional token environment variable is only the default-account fallback; configure distinct native account fields with distinct protected references and explicit bindings. Establish allowed people before enabling a bot. Account binding is routing inside the sandbox, not agent isolation. Probe real two-bot delivery and token rotation/reload before claiming parity. [Account examples](https://github.com/openclaw/openclaw/blob/v2026.11.2/docs/concepts/multi-agent.md).
- Probe file-reader permission checks against enclos's protected outside-home secret location, account ref activation, child exec environments, secret persistence/redaction and missing/rotated refs. An unresolved active reference must never trigger fallback to startup-environment secrets. Runtime login and any runtime-created backups remain inside the sandbox.

## Mobile channel and parity limits

**Recommended seam (inference):** an installed TypeScript channel plugin inside OpenClaw, with one authenticated Unix socket/account per enclos agent, preserving ADR 0042's bridge-dials-in direction. Use one runtime plugin package with explicit account/agent routing, not Hermes's per-profile plugin layout. Channel contracts own inbound security, conversation grammar, outbound media and optional activity; core owns dispatch and session keys. Unix sockets, account discovery/hot reload and enclos's durable outbox remain to implement/probe. [Channel SDK](https://github.com/openclaw/openclaw/blob/v2026.11.2/docs/plugins/sdk-channel-plugins.md), [routing hooks](https://github.com/openclaw/openclaw/blob/v2026.11.2/docs/plugins/sdk-channel-plugins/sessions-and-bindings.md), [ADR 0042](../adr/0042-a-bridge-on-each-host-serves-the-mobile-app.md).

| --- | --- |
| Direct conversations, Home, groups | Explicit account/agent/session mapping. Default DMs may collapse into the agent's main session: use a distinct stable native session for each enclos conversation/group member. Preserve bridge-owned person/owner/history and Home fallback. Do not enable OpenClaw's own group coordinator for bridge-managed groups. |
| Text, typing, titles, tools, commands, files/HTML | Native channel outbound/formatting and runtime hooks exist; verify exact event attribution and command catalogue. A read-compare-RPC sequence is not M4's atomic compare-and-mutate contract. Require a supported conditional native seam/upstream change, or mark affected controls unavailable/read-only. Never write native storage or add a bridge scheduler. [Cron schema](https://github.com/openclaw/openclaw/blob/v2026.11.2/packages/gateway-protocol/src/schema/cron.ts). |

The table's ordinary delivery/event mappings are proposed integration work, not implemented capabilities. Confirm runtime-owned routine timezone/schedule semantics, delivery authorization, create retry receipts after deletion, bounded pagination and exact manual-run acceptance. Unsupported native fields/targets must remain read-only rather than be erased.

**Alternative:** an external Gateway RPC adapter can start/cancel runs and inspect history, but is not automatically a channel with proactive/scheduled delivery. It introduces paired operator identity, scopes and TCP/control-plane access. The official guide recommends RPC for external apps and Plugin SDK only for in-process code. Do not choose the alternative merely to avoid writing a channel or expose it directly to mobile. [External integration guide](https://github.com/openclaw/openclaw/blob/v2026.11.2/docs/gateway/external-apps.md).

Gateway streaming is not a durable event-replay service: reconnect re-subscribes, reloads authoritative `chat.history`, adopts exact active run ids and reconciles per-run sequence numbers; outer connection sequence resets. The channel must still persist enclos outbound ids until acknowledged and deduplicate ingress. Probe disconnect after native acceptance, before bridge acknowledgement, during generation and after final persistence; never replay a mutation on ambiguity. [Client recovery](https://github.com/openclaw/openclaw/blob/v2026.11.2/docs/gateway/clients.md).

All Plugin SDK APIs are explicitly **experimental**. Pin and test the runtime/plugin pair and declare only tested compatibility. ADR 0029 runs installers as served; it does not justify an embedded channel plugin silently loading against an untested ABI. Decide whether runtime selection is versioned or the app capability is refused with an actionable mismatch. Bundle a normal self-contained plugin artifact and manifest with resolved runtime dependencies, not raw TypeScript assuming repository dev dependencies. [SDK stability](https://github.com/openclaw/openclaw/blob/v2026.11.2/docs/plugins/sdk-overview.md), [plugin packaging](https://github.com/openclaw/openclaw/blob/v2026.11.2/docs/plugins/building-plugins.md), [ADR 0029](../adr/0029-runtime-installers-run-as-served.md).

## macOS probe requirements before implementation claims

1. Protect host state first. Use disposable enclos state/home, record macOS/architecture, runtime/package/Node/plugin versions, installer hash, commands, endpoint log and denials. No global install or upstream native service. Verify install/setup/status and that another sandbox cannot read either host state or protected secret files.
2. Start two sandboxes with two agents each; prove independent state/ports/auth, native roster/default transitions (including deleting `main`), partial failures, stop/removal and adoption. Verify JSON5/includes/linked or outside-home configured paths are refused or reported unknown by host observations.
3. Prove supervisor/readiness/restart ownership, marker inheritance, startup failure/exit 78, listener family/root-versus-member/port collisions, service settings changes, live TUI and authenticated headless dashboard. Include CLI use before service startup and after restart; never allow all host loopback.
4. Use test provider access and two real test bots only when authorized for the implementation/probe. Verify protected SecretRefs, per-account/person routing, no secret launch argv/environment/log/config persistence, failed resolution and rotation. Measure optional browser/tool behavior separately.
5. Build/load the packaged channel against the exact installed version. Exercise direct/Home/group conversations, cross-conversation attribution, tools/titles/commands, files/HTML, proactive output, native stop and late replies, restart/reconnect/outbox replay and duplicate ids. Test through the existing Android app after protocol-level fixtures pass.
6. Gate each structured capability on native evidence: complete questions/batches/skip/expiry; exact native approval identities/actions/terminal receipts/two-device races; routine conditional updates/delete/run and lost create replies. If a native contract cannot uphold M4, record the unsupported case and required protocol/upstream decision before claiming parity.

Linux CI can continue throughout, but real bubblewrap/network-namespace/relay/Landlock/channel-socket/dashboard/proxy acceptance remains unverified until the new host exists. macOS results must not be reported as Linux results.
