# Hermes command approvals

Source inspection on 2026-11-09, pinned to official Hermes commit [`9dcf7714df7a0d49c335925d12d4b017274ee355`](https://github.com/NousResearch/hermes-agent/tree/9dcf7714df7a0d49c335925d12d4b017274ee355). These findings inform proposed [ADR 0053](../adr/0053-runtime-approvals-use-exact-native-requests-and-explicit-scopes.md). The earlier local `e5ea5fd9cc` source lacks the exact prompt identity and additive observer APIs needed here and retains typed fallback.

## Native interface

The messaging hook is `_send_exec_approval_prompt(ExecApprovalPrompt)`. Its prompt supplies a redacted display command, reason, session key, exact `request_id` and final ordered action rows. Keep the base `send_exec_approval` method: it proves the full command was displayed on the card or sent beforehand, otherwise narrowing actions to Deny only. Ordinary flags may remove session/permanent scopes; smart denial restricts override to Once/Deny. Never synthesize a wider set. [Base prompt and visibility flow](https://github.com/NousResearch/hermes-agent/blob/9dcf7714df7a0d49c335925d12d4b017274ee355/gateway/platforms/base.py), [visibility helper](https://github.com/NousResearch/hermes-agent/blob/9dcf7714df7a0d49c335925d12d4b017274ee355/gateway/platforms/base_exec_approval.py).

`resolve_gateway_approval_card(session_key, choice, request_id, ...)` returns the number of exact requests resolved. Missing/stale identity resolves nothing and never consumes the next queued request. The native lock also preserves Deny-only restrictions. The adapter must validate the offered action itself, since this resolver does not enforce every scope flag. The bridge authorizes enclos's host person and current conversation owner; the runtime remains responsible for its gate. [Exact resolver and snapshots](https://github.com/NousResearch/hermes-agent/blob/9dcf7714df7a0d49c335925d12d4b017274ee355/tools/approval.py).

`list_gateway_approvals(session_key)` returns pending copies, matched only by the exact supplied id. `observe_gateway_settle(session_key, request_id, callback)` adds an observer without replacing the core settle hook. It runs after native entry removal, on the waiting worker thread, and reports only `resolved`, `timeout`, `interrupted`, `notify_failed` or `session_closed`. It does not disclose the winning action. Only this adapter's own exact successful resolution can confirm Once/Session/Always/Deny; an external decision closes neutrally. The plugin marshals observations onto its event loop. [Native wait and callbacks](https://github.com/NousResearch/hermes-agent/blob/9dcf7714df7a0d49c335925d12d4b017274ee355/tools/approval_gateway_wait.py).

The card resolver and base platform types appear in the published plugin API inventory. Snapshot and additive observer functions are public, documented source functions used by core, but are absent from that import allowlist. Feature detection is therefore required, and source compatibility does not establish a stable plugin API promise for them. [Published API inventory](https://github.com/NousResearch/hermes-agent/blob/9dcf7714df7a0d49c335925d12d4b017274ee355/hermes_cli/data/plugin_api.json).

The base visibility flow can send a full command through the adapter before invoking the button hook. Enclos marks that native send scope, preserves its text literally without local-image extraction or runtime-notice classification, and refuses an oversized encoded message before outbox persistence. Native failure keeps Deny-only. Full text fallback uses independently fenced command chunks bounded by encoded envelope size, including long fence runs and JSON escapes; it does not split one open Markdown fence across messages. Source-registry/base-method regressions cover commands over 80 KiB without executing them.

## Native lifetime and grants

The native timeout is captured before publication, defaulting to 300 seconds; nonpositive values expire immediately. Timeout, interruption, notifier failure and session teardown do not consent. Native waiters are in memory, so a process restart cannot recreate an old request. Once permits the current operation. Session records applicable native pattern keys for the current session; Always also persists them in the active profile's `command_allowlist`. The adapter resolves the wait and leaves persistence and execution to the native guard in its original profile context. These decisions change no enclos sandbox policy. Pattern keys are Hermes's descriptions of the matched dangerous patterns (for example a recursive delete or a pipe to a shell), not the command: a session or always grant pre-approves every later command matching them, in the profile, whoever speaks. `ExecApprovalPrompt` does not carry them; the request's `list_gateway_approvals` snapshot does, as `pattern_key` and `pattern_keys`, and the adapter shows those with Session and Always, offering neither when they are missing. Revoking an always grant means removing its entry from `command_allowlist` in the profile's `config.yaml`: the gateway re-reads the file's delta on every check, so a removed entry stops counting without a restart; nothing in Hermes's approval API removes one. [Allowlist sync](https://github.com/NousResearch/hermes-agent/blob/9dcf7714df7a0d49c335925d12d4b017274ee355/tools/approval.py). A typed `/approve` is answerable by the turn's requester and the profile's `approvals.approvers` (every user when unset), checked by Hermes against the sender it is told about; the enclos channel authorizes every person the bridge relays, so the bridge refuses typed approval commands from everyone and the channel answers them itself ([ADR 0060](../adr/0060-the-bridge-signs-runtime-approval-decisions.md)): a runtime approval is decided only on its card. [Typed commands](https://github.com/NousResearch/hermes-agent/blob/9dcf7714df7a0d49c335925d12d4b017274ee355/gateway/slash_commands.py). [Native context](https://github.com/NousResearch/hermes-agent/blob/9dcf7714df7a0d49c335925d12d4b017274ee355/tools/approval_context.py), [grant handling](https://github.com/NousResearch/hermes-agent/blob/9dcf7714df7a0d49c335925d12d4b017274ee355/tools/approval.py).

Older native versions or unsupported delivery retain Hermes's typed `/approve`, `/approve session`, `/approve always` and `/deny` path. A definitive unsupported button hook uses text fallback; an ambiguous delivery timeout is not resent. There is no new model-invoked approval tool: the existing dangerous-command guard creates its own request. [Runner delivery and fallback](https://github.com/NousResearch/hermes-agent/blob/9dcf7714df7a0d49c335925d12d4b017274ee355/gateway/run_turn_runner.py).

Enclos's existing group discussion queue is a compatibility limit: ordinary typed messages wait behind the running group turn, so they cannot unblock its pending approval. Structured controls directly address the originating member's native request and bypass that queue. Text fallback is a usable approval path for direct/Home conversations; an older client in a running group needs updated controls or another native approval surface. This is an enclos routing limitation, not a native request-id guarantee.

## Verification boundary

Tests use isolated protocol/store/socket flows, Android controls/cache and a temporary native-source registry with simulated waiting work. They do not run the screenshot's command, start a model or live gateway, change a real profile's grants, or install an app on a phone. Live gateway, profile persistence and platform probes remain in the design and app spec.
