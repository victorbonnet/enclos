01 / Room to work

Fewer questions.
The same walls.

An agent that asks before every step is slow. One with your whole computer is a risk. In a sandbox, it gets on with the work, inside limits you can read.

✓Free to do

  • Install tools, packages, and skills
  • Run code and write files in its own home
  • Browse and call the public web, every connection logged
  • Keep working in the background

×Out of reach

  • Writing to your files
  • Reading SSH keys, credentials, browser data, and mail
  • Your local network, your computer’s own services, and cloud metadata
  • Opening apps, sending Apple Events, or signaling other processes

→Your call

  • Other ports and private addresses, when you allow them
  • Allowlist mode: only the sites you list
  • What to allow after a refusal, without a restart

Worth knowing: the agent can still send what it can read to a public website. For sensitive work, put its sandbox in allowlist mode.

02 / One place

More agents.
Less to keep track of.

As you add agents, it gets harder to remember where they live, what’s running, and what they can access. enclos brings the agents in its sandboxes into one local workflow, with a central overview and a policy around each sandbox.

A home of its own

The agent can install tools and write files in its sandbox home. By default, it cannot write to your other files, and sensitive paths such as SSH keys, browser data, and cloud credentials are blocked from reads.

03

A say in where it connects

Every connection goes through the sandbox’s own proxy and is logged. The agent can browse the public web; your computer’s own services, your local network and cloud metadata addresses stay out of reach. Prefer a short list? Switch the sandbox to allowlist mode, then allow what you trust—without restarting the agent.

One policy per sandbox

Each sandbox reads its limits from one small file. Give an agent a folder to write, hide more of your files, or keep it to the sites you list. enclos policy show lab shows what is in force.

Every change becomes a new version, recorded in the audit log, and the same file is meant for every kind of sandbox enclos will support, each stating how well it enforces each rule. Whatever the file says, your keys and credentials, other sandboxes, and your computer’s own services stay out of reach.

POLICY.TOML
# ~/.enclos/sandboxes/lab/policy.toml [filesystem]# a folder it may writewrite_add = ["~/Documents/notes"]# more of your files to hideread_deny_add = ["~/work"] [network]# only the sites listed heremode = "allowlist"allow_add = ["api.telegram.org"]

The sandbox is the boundary. Agents inside it share the runtime, policy, proxy, and login. Use separate sandboxes when those need to differ.

06 / A few useful answers

Know what
you’re getting.

Clear boundaries also mean being clear about the limits.

Read the threat model ↗
Is enclos an AI agent?+

enclos creates and manages sandboxes for agent runtimes. The runtime installed in a sandbox provides the agents, conversations, and tools: Hermes today, with Claude Code and Codex planned. You use your own supported model-provider account.

Can I manage all my agents in one place?+

enclos gives you one CLI to manage and see the agents in the sandboxes it creates on your computer. Run enclos status for an overview, then use the agent and sandbox commands to add or remove agents, start or stop services, and clean up unused sandboxes. Hermes is supported today; agents installed elsewhere and other machines are outside this overview.

Can it read the rest of my files?+

Host reads are broad by default, with a deny list for sensitive paths such as SSH keys, cloud credentials, browser data, mail, and other agents’ configuration. Other sandboxes and enclos’s own protected files are also blocked. Writes are limited to the sandbox’s own home by default. This is not a policy that hides every file on your computer.

How strong is the protection?+

enclos is designed to reduce accidental damage from buggy or misled agents you mostly trust. It uses the operating system’s own sandbox, Seatbelt on macOS today, and probes known escape routes. That sandbox shares your computer’s kernel: it is light, and it is not a defense against deliberately malicious code exploiting the kernel. A passing probe does not prove every possible route is closed.

Does it need a virtual machine or Docker?+

No. enclos uses your operating system’s own sandbox, Seatbelt on macOS today, so a sandbox starts at once and adds little beyond the agent itself and its small proxy. Most of the disk space a sandbox uses is its runtime’s own install, such as Hermes’s. Containers and micro virtual machines are planned for agents that run untrusted code: heavier, with a kernel of their own, and the same policy file.

Can the agent send my data anywhere on the web?+

By default it can reach public websites on ports 80 and 443, so anything it can read could be sent to one; that is why sensitive paths are denied and every connection is logged. For HTTPS the proxy records where it connected, not the encrypted content, and a remote service may fetch other sites on the agent’s behalf. For a tighter limit, put a sandbox in allowlist mode so it reaches only the domains you list.

Can I have agents with different access?+

Yes—put them in separate sandboxes. Agents in one sandbox share its runtime, policy, proxy, and login. Agents created with the runtime’s own commands inside a sandbox are reported by enclos; enclos agent add lab/scout explicitly tracks an existing agent without recreating it.

What works today, and what’s still coming?+

Today’s milestone runs Hermes on macOS with sandbox homes, network policies, connection logs, background services, agent discovery, a status overview, escape probes, and the command audit log. Chromium browser tools do not work inside the sandbox yet. Linux, other runtimes, messaging integrations, and managed secrets are future work.

Does it change my existing agents?+

enclos manages only sandboxes it creates. Each sandbox has its own runtime install and login; it does not adopt your existing host installation. You can inspect sandbox services with enclos sandbox show lab and stop them with enclos sandbox stop lab.
