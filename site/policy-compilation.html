How a policy compiles

You write one small file. enclos checks it when it changes, and compiles it each time a program starts in the sandbox.

1. Layers become one policy

A sandbox’s policy.toml only says what differs. enclos applies four layers in order:

  1. Built-in defaults: writes only to the sandbox’s home, and the list of sensitive paths it may not read.
  2. The template: minimal, mcp-only or assistant, which the file names with extends.
  3. The runtime’s needs: the hosts its install, login and model calls use.
  4. Your policy.toml: what you add.

A list written write_add adds to the layers below, and one written write replaces them. Unknown keys are errors, so a misspelling cannot pass unnoticed.

2. The policy is checked and stored

enclos checks the result before keeping it. It refuses what it will not grant, such as dropping an entry from the sensitive list, writing to enclos’s own folders, or allowing localhost. It rejects what it cannot read, such as a malformed address.

A policy that passes is stored as an immutable version. enclos policy history lists them, and enclos policy rollback brings an earlier one back as a new version.

3. The backend compiles it

Each time a program starts in the sandbox, enclos takes the active version as stored, checks the sandbox’s paths as they are now, and hands the policy to the sandbox’s backend. If that backend cannot run on this computer, the command fails, with no fallback.

On macOS, the Seatbelt backend writes a file named after its content, compiled/<hash>.sb, and the program runs under it through sandbox-exec. Rules start from (deny default), and later rules decide:

Part of the fileWhat it doesFrom your policy?
WritesDenies all writes, then allows the sandbox’s home and the folders you grantedYes
Sensitive pathsDenies reads and writes after the allows, so no grant reopens themYes
NetworkDenies the network, then allows only the sandbox’s proxyOnly whether it may listen
Host servicesBlocks opening apps, Apple Events, launchd jobs, the pasteboard and signals to other processesNo
enclos’s own filesDenies other sandboxes’ folders and enclos’s recordsNo

4. The network stays with the proxy

Your allowed hosts are not in the compiled file. It only sends every connection to the sandbox’s proxy, which reads the active policy for each new connection. So a change to the network applies at once, without a restart.

The compiled file is fixed for the life of a program. A change to what a sandbox may write therefore reaches running sessions only when they restart:

You changeNew sessionsRunning sessions
Network hosts or modeUse itUse it at once
Files, listening, secrets or limitsUse it, once it is activeWait for enclos policy apply

What a backend cannot enforce is refused

enclos refuses what a backend cannot enforce, rather than keep it and ignore it. On Seatbelt today, an [exec] section is refused, and so are limits on CPU time, memory, file size and CPU share.

The same policy.toml is meant to compile for every backend, each with a compiler of its own. Only Seatbelt ships today, so this is the design, not yet shown. bubblewrap on Linux is next.

The templates

A sandbox starts from a template, named when it is created and kept in extends. Change extends with enclos policy edit lab to move it to another. The templates differ only in what the sandbox reaches on the network:

Can it…minimalmcp-onlyassistant
Write to its own homeYesYesYes
Write to other foldersIf addedIf addedIf added
Read your files, except sensitive pathsYesYesYes
Read sensitive paths, such as SSH keysNoNoNo
Run programs, and install them in its homeYesYesYes
Reach what its runtime needs, once installedYesYesYes
Reach the public webIf listedIf listedYes, ports 80 and 443
Reach other portsIf listedIf listedIf listed
Reach a host on your local networkIf you opt inIf you opt inIf you opt in
Reach your computer’s own services or cloud metadataNoNoNo
Open apps, send Apple Events or signal other processesNoNoNo
  • minimal reaches nothing until a runtime is installed, then only what that runtime needs and what you list. For Hermes, that is its install sources and the ChatGPT subscription’s hosts; another model provider’s hosts need enclos policy allow. Use it when an agent should reach only what you name.
  • mcp-only has the same rules as minimal for now. Use it for assistants working on outside data through remote MCP servers: allow each server’s host, then tell the runtime of it with its own commands.
  • assistant adds any public address on ports 80 and 443, so any model provider works without a grant. Use it for personal agents that browse, research and call public APIs. It can send what it reads to a public website: for sensitive work, use an allowlist.

Under every template, each connection goes through the sandbox’s proxy and is logged. A runtime may also ask to listen on TCP, as Hermes does, and then anything in the sandbox can serve your network. A runtime’s hosts can be broad: Hermes’s include github.com and storage.googleapis.com, which could carry data out.

Every setting

A policy.toml holds what differs from its template. These are all the keys there are: any other key or section is an error. Change a sandbox’s file with enclos policy edit lab.

extends = "assistant"

[filesystem]
write_add = ["~/Documents/notes"]
read_deny_add = ["~/work"]

[network]
mode = "allowlist"
allow_add = ["api.example.com", "*.example.org", "printer.lan"]
private_add = ["printer.lan"]
log = "metadata"

[resources]
open_files = 1024

[secrets]
env_add = { API_TOKEN = "secret:lab/api" }

[secrets.agents.main]
env_add = { TELEGRAM_BOT_TOKEN = "secret:lab/main-telegram" }

[network]

A destination is host, host:port or *.domain, for its subdomains; the port is 443 unless written. *, *.com, localhost and loopback addresses are refused. A change applies at once, except listen, which waits for sessions to restart.

SettingAcceptsNotes

listentrue, falseWhether the sandbox may listen on TCP. Off by default, and Hermes turns it on. Leave it unset: its gateway exits if it cannot listen.

[secrets] and [secrets.agents.<agent>]

A grant maps a variable to secret:<sandbox>/<name>, a secret of this sandbox stored first with enclos secret set. Variables enclos sets itself, such as PATH, are refused. A change waits for sessions to restart.

# compile it, then try known ways out from inside
enclos policy test lab
